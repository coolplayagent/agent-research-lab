# 可复用研究输入

这些条目是下一轮实验的输入，不是系统权限或评测规则。每轮从本项目远端默认分支的固定提交读取本文，将正文、来源提交及 SHA-256 绑定到任务。详细知识与完整记录仍归档到 SuperPOD；这里保留可公开、可迁移的结论和可证伪假设。旧版本观测需要在当前基线复现，才可支持新的缺陷或收益结论。

## I-001：进程成功不等于工具动作成功

- **状态：启动阶段观测。** 2026-10-09 的早期隔离探针中，Codex 能完成模型回合，但缺少 `codex-code-mode-host` 时不能实际读取文件。挂载匹配的工具宿主后，后续探针记录到 `command_execution` 退出码 0。
- **证据与版本：** [启动 PR #1](https://github.com/coolplayagent/agent-research-lab/pull/1)；修复与回归位于 [4c9a42f 的 isolation.rs](https://github.com/coolplayagent/agent-research-lab/blob/4c9a42fb4438cb039b1a6eae73021ec4b0f8928d/src/isolation.rs)。真实探针发生于开发过程，不是最终提交的等预算对比实验。
- **启发：** 任务验收至少区分进程退出、工具动作、可观察结果、研究断言四层。版本探针或模型的自然语言确认只覆盖其中一部分。
- **下一实验：** 注入缺失工具宿主、权限拒绝、工具退出非零三种故障，比较只检查进程退出与检查任务结果的误判率。独立评测器读取宿主记录与目标文件摘要。
- **限制：** 本观察没有证明整体任务成功率提升。

## I-002：新版本必须重新成为实验基线

- **状态：工程约束与一次仓库审计。** 2026-10-09 核对发现，正式发布的 skill 可以是最新版，同时本地代码仍停在非默认分支。relay-knowledge 的本地研究分支与远端 `main` 当时有不同提交。
- **可复现检查：** 分别记录默认分支、远端提交、技能包版本与摘要、实际二进制摘要；在独立 worktree 检出远端提交，保留用户正在使用的分支。
- **启发：** 最新 skill、最新源码、二进制的构建来源是三个不同事实。发布二进制缺少某功能，不能直接推断最新源码仍缺少它。
- **本轮新增反例：** 初次联网核验时 relay-knowledge 最新正式版为 v1.1.18；本轮工作期间上游发布 v1.1.19，另一会话更新了安装目录。随后真实 doctor 检查以“installed skill tree differs from host manifest”拒绝旧清单。该记录只证明这一次并发升级被识别，不代表所有竞争条件都已覆盖。
- **下一实验：** 入队后推进远端默认分支或发布新 skill，验证旧任务停止新执行、旧结果仍可审计、新轮次使用新提交；再测试评测后上游更新是否阻止晋级。
- **限制：** 最新仅指成功联网核验时的状态。成对实验内部保持版本固定；变化后建立新实验，禁止混用新旧观测。

## I-003：续作记忆要区分任务身份与执行尝试

- **状态：有界集成测试通过。** 同一个任务的第二次 attempt 能读到第一次保留的记忆，另一任务的初始记忆为空。
- **证据与版本：** [4c9a42f 的运行器测试](https://github.com/coolplayagent/agent-research-lab/blob/4c9a42fb4438cb039b1a6eae73021ec4b0f8928d/src/runtime.rs)，真实 relay-memory SQLite 后端；测试名 `real_memory_survives_attempt_change_and_isolates_experiments`。
- **启发：** 记忆按稳定任务身份保留，日志按 attempt 保留；二者混用会导致重试失忆或跨实验污染。可复用知识需要研究归档，不能把所有任务记忆直接共享给所有 agent。
- **下一实验：** 在相同任务集与模型预算下比较无记忆、隔离任务记忆、经审查共享摘要，测量恢复成功率、错误继承率和额外 token；以未见任务族检验迁移。
- **限制：** 当前测试不覆盖跨机器、远程后端或长期记忆收益。

## I-004：更新请求已接受，不代表知识索引已可用

- **状态：真实 CLI 核验与回归测试。** relay-knowledge 1.1.18 的活动任务位于返回对象顶层，完整性通过 `status.content_integrity.state` 表示。只读取内部的活动任务字段会漏判。
- **证据与版本：** [4c9a42f 的知识适配器](https://github.com/coolplayagent/agent-research-lab/blob/4c9a42fb4438cb039b1a6eae73021ec4b0f8928d/src/knowledge.rs)。启动验收记录已在 SuperPOD 合并，并对指定 `knowledge/software` 范围完成精确提交索引；这不是全库检索质量证明。
- **启发：** 后续任务需要目标提交一致、索引非陈旧且内容完整；提交成功、队列存在和进度百分比都不能替代这些条件。
- **下一实验：** 注入排队、维护中、部分内容和旧提交四种状态，验证不重复启动写入、不提前宣告可查询；以命中和不命中的问题分别检查检索结果。

## H-001：保留分歧可能提高实验的信息价值

- **状态：假设，未确认收益。** 独立研究、独立质疑再综合，可能比直接达成共识更容易发现反例，也可能只增加成本。
- **竞争解释：** 收益来自更多推理预算、不同模型或角色提示词；也可能没有稳定收益。
- **下一实验：** 固定任务族、模型预算与成功判据，对比单 agent、同模型多角色、不同模型多角色，进行多任务族重复成对试验。单独移除质疑阶段、交换角色提示词，评估消融结果。
- **记录要求：** 保存少数观点及其可区分预测，测量成功率、严重回归、耗时和 token。提示词变体需有父版本与变更原因，不根据说服力或共识数量晋级。

## H-002：恢复策略应由外部动作的可观察性决定

- **状态：设计假设与协议测试，尚无长期对比。** 只读失败可以有界重试；写操作中断后，其结果可能已经发生。工作流测试区分了这两种情况。
- **证据：** [4c9a42f 的 workflow 协议测试](https://github.com/coolplayagent/agent-research-lab/blob/4c9a42fb4438cb039b1a6eae73021ec4b0f8928d/src/workflow.rs)。
- **下一实验：** 在提交前、提交后但回执前、回执持久化后三个时间点终止进程，测量重复副作用、恢复时间和对账次数；比较稳定操作 ID、目标状态查询与内容摘要的作用。
- **限制：** 单进程协议测试不能证明所有远端服务都具有相同幂等行为。

## I-005：工作流完成与后处理完成是两个检查点

- **状态：恢复回归测试覆盖，尚未做长期运行对比。** 模型结果已提交到工作流之后，控制器仍可能在记忆写回或后续任务入队之前崩溃。只有一个“成功”标记会丢失这段未完成的工作。
- **证据：** 本项目的 [运行器与恢复测试](../src/runtime.rs) 分别保存工作流确认的结果、后处理日志和子任务身份；[租约测试](../src/lease_heartbeat.rs) 检查前台阻塞时仍续期，以及失去续期能力时停止工作进程。协议替身测试只验证控制器状态处理，不代表远端服务已执行相同故障实验。
- **启发：** 区分“结果已确认”“后续动作待执行”和“外部写入结果未知”。已确认结果可以重建待办；写入结果未知需要对账；确定性子任务 ID 可以让部分入队安全续作。租约续期也不能依赖前台研究步骤及时返回。
- **下一实验：** 在同一组长程任务中，随机中断模型执行、结果提交和后处理阶段；固定预算，比较结果遗失、重复写入、重复子任务和恢复耗时。将后台心跳延迟、数据库锁等待及跨日预算切换纳入故障注入。
- **限制：** 可恢复的执行机制不是研究质量提升的证据；仍需独立评测研究结论。

## I-006：续作记忆需要独立于审计快照的内容预算

- **状态：一次真实运行观察与适配器修复。** 2026-10-09，真实模型读取 I-005、项目提交 `a8c981f` 并执行 relay-knowledge 1.1.19 后完成任务。控制器向 relay-memory（源码 `e188a5b` 的本地构建）写回整份实验回执：13,277 个字符，而 agent 报告约 610 个字符；写回触发了 20 秒时限。
- **对账：** 控制器将写回标为结果未知，没有自动重放。停止后的私有 SQLite 只读检查显示该会话事件与主题均为零。这个结果只描述该 SQLite 实例，不能推广为所有后端中断都会回滚。
- **启发：** 审计回执保留完整输入与版本绑定；续作记忆需要简短结论、未决问题和不可变回执引用，并明确标记截断。独立控制二者的内容预算，可以验证记忆是否帮助继续工作。
- **证据与下一实验：** [运行器的检查点与真实记忆测试](../src/runtime.rs)。固定工具构建、存储和任务集，对比完整回执、限定大小的检查点与无记忆，测量写入延迟、检索命中、遗漏关键决策和恢复成功率；分别改变内容长度和重复元数据比例。
- **限制：** 这次超时未单独证明输入长度是唯一原因，也不直接构成上游 CLI 缺陷结论。需在最新源码构建上做上述受控对比。

## I-007：权限、目标可用性与动作证据需要分别验证

- **状态：真实本机观察与目标适配。** 2026-10-10，任务 Codex 已设置 `approval_policy=never`、`sandbox_mode=danger-full-access`，但目标环境缺少 X11 工具；嵌套 Bubblewrap 仍被本机 AppArmor 拒绝。全批准设置不等于操作系统已经提供目标资源。
- **证据：** [权限默认值](../src/agent_policy.rs)、[专用桌面生命周期](../src/targets/desktop.rs) 和 [目标验证入口](../src/targets/mod.rs)。computer-use v0.1.0 在专用 Xvfb/GTK 目标上完成真实窗口枚举、截图、输入与文本回读。首次进入 agent 的实际隔离环境时，Xvfb 又因加载宿主 GPU 驱动崩溃；纯文本目标关闭 GLX，保留软件绘制路径。
- **启发：** “未配置真实目标”可能是产品的启动和资源管理缺口。将专用目标的创建、观察、动作结果与回收纳入实验，可把停滞转化为具体工程问题。验证必须经过实际 agent 的挂载、环境变量和进程生命周期，宿主上的成功不能直接迁移。
- **下一实验：** 固定 CLI 与模型，分别注入缺依赖、失效显示器、只读挂载、嵌套 namespace 拒绝、动作后断连；比较泛化权限重试与按层诊断修复的恢复率、错误副作用和耗时。保持宿主审批策略不变，隔离目标管理本身的贡献。
- **限制：** 自有文本应用不是任意 GUI 工作流；本地每次执行的 namespace 也不等于持久容器或远端 VM。当前结果不证明长程任务或提示词进化带来能力收益。

## I-008：模型输出协议必须与后续任务的权限规则一致

- **状态：一次持续运行审计。** 基于项目 `8b57a47` 的 45 份后续任务日志中，33 份被拒绝：30 份来自无入队权限的独立研究/评审，另 3 份综合结果使用 `research` 角色却要求 `write=true`。这 3 批没有合法同级提案；“非法项导致合法项连带丢失”是回归测试覆盖的风险，不是本轮已观察事实。
- **证据：** [运行器的任务 schema、逐项校验与恢复测试](../src/runtime.rs)。新的提示词和 schema 提前约束角色与写权限，合法提案按原始索引独立入队，拒绝项保留原因；历史拒绝记录不会在升级后自动重放。
- **启发：** 长程 agent 停止可能来自规划输出与调度协议的不一致。仅改写研究提示词或允许更多权限，不能替代调度层清晰的契约与幂等处理。
- **下一实验：** 固定模型和研究主题，对比通用 schema、角色约束 schema、角色约束加逐项接纳，测量可执行后续任务率、错误提案率、重复入队与研究质量。独立评审检查任务的实际意图，避免只优化“可入队率”。
- **限制：** 这里是单环境运行观测与协议回归，不是跨模型的因果效果估计。

## I-009：依赖可达性与候选实现质量必须分别归因

- **状态：一次真实写任务与隔离构建观察。** 2026-10-10，任务的私有 Cargo/Bazel 缓存为空，下载依赖时发生 TLS 失败，Qualitygate 的 Clippy 与 Bazel 检查未完成。该结果既不是门禁通过，也不足以判定模型实现本身错误。
- **证据：** [缓存准备与回归测试](../src/build_cache.rs)、[隔离环境](../src/isolation.rs)。从当前锁文件及经过摘要验证的上游规则元数据选取依赖，复制到每个任务独立的可写缓存；在全新生产隔离目录中，离线 Clippy 与禁止仓库下载的 Bazel 构建、打包通过。缓存准备标记不具有评测通过的含义。
- **边界：** 同一环境的完整测试实际执行后，四项控制器隔离测试因外层禁止嵌套 namespace 而失败。不能在这个环境内证明控制器自身的隔离能力；候选仍须由可信宿主独立执行完整门禁，不能跳过正式测试或放宽 agent 边界。
- **下一实验：** 固定源码、模型和任务预算，对比空缓存、精确依赖缓存与依赖网络故障，分别记录准备耗时、网络失败、构建结果和宿主评测结果，避免把基础设施失败混入模型成功率。
- **限制：** 单次构建成功没有证明候选变更正确、长期任务成功率提高或提示词进化有效；缺失的依赖仍可能需要网络。

## I-010：共同知识库需要明确的读取与更新契约

- **观察：** `2a328407` 已为所有角色固定 SuperPOD 提交和只读路径，但只有研究角色明确要求先读知识入口。路径可见不能证明知识已进入上下文，更不能证明模型理解了它。
- **改进：** 通用输入现在携带三个 SuperPOD 入口的有界正文、完整文件及摘录摘要；所有角色据此查阅相关来源，并在持久结果中提出带目标路径、基线、证据和反例的知识更新。详细知识仍只存 SuperPOD，独立任务记忆不承担共享知识库职责。
- **边界：** Git 对象与摘要检查只验证来源和传递一致性。知识更新需要宿主核验并串行合并；精确版本索引完成后，后续研究再使用新知识。发送上下文、引用存在和结论正确是三件事。
- **下一步：** 固定模型、任务及调用预算，对比仅提供路径与提供入口摘录的任务相关引用覆盖、错误引用和宿主确认的有效更正；同时记录上下文开销。若两者无差异，缩小入口包而非继续堆积内容。

## I-011：输出契约歧义会让已完成的研究报告失效

- **观察：** 2026-10-10，基于 `e2d32394` 的一个真实协作实例完成了 32 次 workflow 任务，观察到同时存活的 worker 峰值为 8。严格收集器接纳 14 份卡片报告，另 18 份因不安全的本地 ID 被拒绝；逐份核对发现，这 18 份都把自身的 `task-id#local-id` 写进了 `id` 字段。接纳结构不等于结论正确，worker 并发也不等于 provider 同时推理。
- **契约缺口：** [v1 任务文本](https://github.com/coolplayagent/agent-research-lab/blob/e2d32394a9e450549445bfb69c1c712d9078ef22/src/collaboration_experiment.rs) 同时要求本地安全 ID，又给出“你的卡片前缀是 task-id#”。宿主实际负责补全前缀；只有跨卡引用使用完整 ID。两种表述增加了遵循错误的可能，不能据此给出通用模型能力排行或协作收益结论。
- **改进与下一验证：** v2 明确区分 `id=c1` 与引用 `task-id#c1`，保留 v1 的精确历史重放和严格收集规则。先用新的独立实例验证清晰契约的可执行性，保留失败、无效报告与实际资源开销；不修改旧报告、不重试旧实例，也不将协议修复验证直接解释为研究质量的因果提升。完整知识记录仍统一归档到 SuperPOD。
