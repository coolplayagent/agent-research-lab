# 成果协作

主页进入会话，每个群都有自己的成果看板。人描述意图，内置 coordinator 负责拆解、分配、检查与汇总；最终成果由人验收。协作主题和研究对象已删除，不需要先创建主题或关联成果路径。

## 开始任务

1. 创建群聊或私聊，并在“设置 → 数字人管理”完成成员的执行绑定。
2. 在研究群里直接发送意图。Coordinator 会回复、澄清、补充已有意图或创建新成果任务；也可以在本群成果看板中明确发起任务。回复某条协作消息会关联其意图；无法判断归属时先询问。同群支持多项意图。私聊和公告不自动触发协调。
3. coordinator 自动复用首个仍有效的已验证执行配置；可以在“设置 → 内置协调者”单独选择适配器、模型并测试协调能力。首次执行会自动做协议测试。
4. 信息不足时补充回答；信息齐全后任务图自动执行。只分配当前会话内的可用数字人。
5. 分工、澄清、成员成果、审核与交付会回到群聊，并链接本群成果看板。在任务详情查看交付成果、分层任务图和活动记录。点击节点查看验收条件、上游成果、产出、限制和按次执行日志。
6. 最终成果进入“待验收”。可以验收，也可以填写退回意见，交给 coordinator 调整任务图。

普通聊天中的 `@数字人` 是直接问答，使用独立执行记录，不创建待验收成果任务。会话显示最近问答的状态和执行记录入口。

## 依赖、预算与恢复

节点必须有负责人、预期成果和验收条件。独立节点可以并行，依赖节点只接收已由协调者检查的上游成果。一个数字人可以承担多个节点。

默认累计 32 个节点、每节点 3 次执行、3 次任务图调整、30 分钟活跃执行时间、每次执行 300 秒。重试、换人和新增节点都计入原预算；等待人工补充或验收不累计活跃时间。达到上限时暂停，可调整预算。适配器不可用时修复配置后恢复执行。

任务、图版本、执行尝试和成果持久化在协作存储服务。重启后按租约恢复，超时尝试不能提交；取消后的结果也不能推进任务。任务图替换会使受影响的下游成果失效，历史成果和分工仍保留在执行记录中。

## 验收与证据

“数字人已提交”“协调者已检查”“人已验收”“证据已验证”是不同事实。协调者不能代替人验收，也不能把自己的判断写成独立证据验证通过。

节点成果自动保存会话、任务、节点、执行尝试、上游引用和执行凭据。点击“查看成果记录与验证”可查看已有证据流程。没有可核验仓库证据的普通回答保持未验证；人工验收任务不会改变这个状态。向外部知识库发布仍需要原有证据验证和接受记录。

## API

- `GET/POST /api/v2/collaboration/tasks`：必须按 `group_id` 分页读取任务，或按 ID 读取（可同时限制所属群）；创建、补充、恢复、调整预算、取消、验收、退回。
- `GET/POST /api/v2/collaboration/questions`：会话内直接问答及独立执行记录。
- `GET/POST /api/v2/collaboration/coordinator`、`POST .../coordinator/test`：协调者配置及实际协议测试。
- `/api/v2/collaboration/outcomes`：成果记录，使用 `group_id` 和 `goal_id`；任务节点成果还包含 `node_id`。验证和知识发布子接口沿用原有门槛。

任务创建只需 `input: {id, group_id, intent}`，预算可选。修改带当前 `revision`；过期修改返回稳定冲突代码。执行认领、提交和协调提案只能由主机运行时经存储协议提交，浏览器及数字人令牌不能伪造。

旧主题、研究对象及路径接口已退役。旧成果 v1 接口返回协议升级错误。schema 10 离线迁移删除主题、研究对象、所属会话关联目标、成果和专属证据；普通聊天及无主题关联的目标保留。外部知识仓库不在清理范围内。

## 消息处理与成员状态

普通管理员消息与处理记录由存储服务原子保存，重试使用请求编号去重，重启后按有效租约恢复。系统及数字人消息不递归触发协作。`MessageProcessingState` 区分排队、处理中、等待补充、暂停、已回复、已关联和已形成任务；“已回复”不代表成果已验收。

数字人空闲时显示在线，有有效执行任务时显示忙碌，全部结束、失败、取消或超时后恢复在线。状态跨群汇总，不依赖长连接数量。执行绑定与服务健康单独提示。

原有任务与成果保留；旧任务链接跳转所属群看板。升级时同步更换核心与存储服务版本，既有记录通过兼容默认字段读取。
