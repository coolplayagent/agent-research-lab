# 03 服务配置与 Agent 接入

[文档首页](../00-index.md) · [本目录](00-index.md) · [English](../../en/guide/03-services.md)

## 绑定 Agent

系统设置默认打开 **Agent 绑定**。先创建数字人，选择 Claude Code、Codex、DeepSeek Harness 或 Pi，然后点击**验证并绑定**。本机 Agent 需已安装并登录；验证会调用模型，可能消耗额度，页面会展示进度及失败步骤。只有验证成功才启用适配器并保存绑定证据。创建身份或保存适配器模板不会调用模型。

完整安装使用 Linux `//:local-package` 或 Windows `//:windows-package`。将 `outcome-hub`、`outcome-hub-storage`、`outcome-hub-services`、`outcome-hub-agent`、`outcome-hub-knowledge` 保持在同一目录（Windows 带 `.exe`）。新工作空间自动启动独立存储服务，执行器、沙箱和知识服务按需启动，无需填写地址。**本机环境 → 一键准备**可提前准备执行环境，不调用模型。首次绑定或执行任务也会自动准备；已启用适配器在重启后恢复服务。Agent CLI 仍需自行安装并登录。

已有 `services.json`、外部部署和旧 `crystal` 数据目录保留原选择，不会自动迁移数据库。独立存储崩溃后最多重试三次，重新打开原数据；数据丢失或恢复失败会明确报错。只有显式使用 `serve --embedded-development` 才为全新工作空间选择嵌入式开发存储。缺少执行或知识程序不会阻止基础聊天；新安装缺少存储程序则拒绝启动，并提示重新安装完整包。

可在 Agent 绑定页直接创建数字人；创建后自动选中，并保留已选 Agent、程序和模型。知识库及群组／目标的默认绑定在“设置 → 知识库”管理；主题级服务绑定已停用。

每个数字人只保留最新一次验证过程和私有诊断；新验证开始后删除旧过程日志，重启时也会整理已有历史。只有新验证成功才替换有效绑定。后台仅保留有界请求指纹，防止旧请求重复调用模型；主动重试应使用新的请求编号。失败输出经过大小限制和脱敏，保存在私有的 `binding-<request-id>.diagnostic.json` 文件中；HTTP 响应只包含稳定错误码与诊断编号。

Codex 登录过期时，验证会返回明确的 `authentication_required` 提示。请在执行服务使用的登录环境中重新登录后重试。如果服务使用独立的 `CODEX_HOME` 配置，可在核心服务和沙箱服务的私有环境中设置 `OUTCOME_HUB_CODEX_AUTH_FILE`，指向当前主机登录文件 `auth.json` 的绝对路径。每次执行重新读取此文件，服务配置和一次性会话目录仍保持独立。指定文件必须存在且是大小受限的普通文件；不可用时不会回退到旧登录。来源文件只读，由所属 Codex 登录维护更新，任务内凭据变化不会写回来源。凭据和登录文件路径不会加入公开配置响应。

执行服务按变量名传递已配置的代理环境。Codex 原生工具宿主以只读方式挂载并计入安装证据。Linux 沙箱的虚拟地址空间上限为 16 GiB，以容纳工具宿主的地址预留；该上限不代表常驻内存保证。时限、文件、输出限制及真实文件挑战校验继续生效。

## 高级部署

折叠的**高级设置**包含外部服务连接、执行适配器和存储。已有页面链接仍可直接打开；离开未保存表单时会提示。

| 组件 | 职责 |
| --- | --- |
| 执行器服务（executor） | 接收版本化执行协议，使用所选沙箱；服务卡片列出引用它的适配器。 |
| 执行适配器 | 通过统一 JSON 协议调用所选 Agent，并关联执行器。 |
| 沙箱服务（sandbox） | 提供有界时长、输出及一次性状态的命令执行环境。 |
| 存储服务（storage） | 独占生产协作数据库，通过 API 提供访问。 |

编辑已有服务时 ID 和职责固定；使用其他职责应新建连接。执行器只能选择已启用沙箱。配置保存会原子校验引用与 revision。

内置 Agent 配置默认禁用，保存时先存为模板，由**验证并绑定**自动生成 bridge 命令。更改执行器或时限后需要重新验证。自定义适配器保留 `json_stdio_v1` 命令数组编辑，启用前必须填写命令。配置存在、服务健康与模型/任务验证是分别展示的证据。

服务托管方式显式区分：`local_managed` 在工作空间私有端点启动随包程序，`external` 连接单独管理的服务。旧配置未填写该字段时继续按外部服务处理，禁用状态、自定义端点也会保留，升级不会自动接管。已有外部部署应先启动其配置的服务，再执行绑定验证。

开发使用显式独立本地存储，生产数据库由一个存储服务独占。修改存储端点前准备目标数据，停止核心后重启生效；不能通过切换端点隐式创建另一份在线库。部署及备份见[维护指南](07-operations.md)。

凭证值只配置在服务环境，适配配置只列允许的环境变量名称，不在 UI、响应或命令参数暴露值。可选挂载只读，网络访问显式配置，每次运行获得一次性工作区。完整帧、请求、输出和当前尝试隔离规则见[服务协议](../design/03-services.md)。

## 外部 worker

创建身份或宿主管理的执行不需要在 UI 申请个人 token。独立受信 worker 通过宿主管理 API 的 `grant` 操作获得短期授权：只返回一次、持久化仅保留摘要、最多 24 小时。宿主写请求须携带精确 Origin、JSON Content-Type 和 `X-Crystal-Intent: manage-crystal`。

worker 领取其分工、遵守返回的截止时间、用相同 claim 和 attempt 提交结果。提交成功后检查群内主持人验收，不把 stdout 或健康状态当完成。接口见[目标与消息 API](../design/02-collaboration.md)。

## 可选研究后端

研究使用另一套本地 `json_process` 文件回执协议。配置片段见 [examples/backend.toml](../../../examples/backend.toml)：`agent_backends` 声明执行器，`role_backends` 选择角色，`[models]` 保持默认模型，可选 `[backend_models]` 为后端列模型。新增模型不创建新身份；未列出时接受既有角色默认模型。

```sh
outcome-hub-cli --config local.toml agents backends
outcome-hub-cli --config local.toml doctor --probe-models
```

模型探测可能消耗额度。通用 bridge 的探测只证明本地 JSON 契约；Codex 模型响应探测和真实任务结果也须分别判断。未知模型或能力不足明确失败，不静默换模型。

## 提案板与规模模拟

启用普通研究共享提案：

```toml
[multi_agent]
shared_research = true
```

配置变化冻结为新任务身份；旧任务保留旧输入，正式协作 pilot 与 holdout 不自动加入。

```sh
outcome-hub-cli --config local.toml agents boards --shard 0 --limit 32
outcome-hub-cli --config local.toml agents view --cohort SHA256
outcome-hub-cli --config local.toml agents simulate --agent-count 1000
outcome-hub-cli --config local.toml agents simulate --agent-count 10000
```

列表按 shard/cursor 分页。`agents close` 阻止新成员，`agents prune` 要求已关闭且过期，先归档所需证据；保留身份 tombstone，不退还额度或发布知识。模拟验证逻辑路由和资源边界，不启动万人模型，不证明研究质量提升。实际执行上限仍为八个 worker。

## 已停用的服务配置

外部场景服务、成果验证服务和主题级服务绑定已停用。私有 `services.json` 若仍含非空 `scenarios`、`outcome_bindings` 或验证器类型的 `outcome_services`，启动会明确失败且不改写文件。请先备份并清理这些条目；历史成果和目标记录保留。内置协作与设计评审场景仍可使用。

## 动态添加知识库

在“设置 → 知识库”点击“添加知识库”，在同一表单选择 Git 仓库或本地目录，再填写名称和本机已有的绝对路径，无需先配置服务端点。默认使用整个仓库或所选目录，可在高级选项中限制内容子目录。新目标默认只读；Git 读取可检测当前分支。空仓库或分离 HEAD 需要先准备可用分支。开启写入必须明确指定已有且未被检出的发布分支。添加不会克隆、创建分支、提交、发布或自动建立默认绑定。

Linux 与 Windows 完整包随附可选的 `outcome-hub-knowledge`，由宿主按需启动并在关闭时清理，目标配置由独立知识服务持有；核心协作仍可在缺少该程序时启动。知识库设置只使用本机托管服务，不再支持外部知识服务连接。升级时会备份服务配置，移除旧外部连接和指向它们的当前默认绑定；历史成果、回执、本机连接及知识文件保持不变。添加后会显示路径、类型、权限和启用状态，可编辑、停用或删除配置。默认绑定可按名称选择已启用的知识库；删除前需解除相关默认绑定，删除配置不会删除知识文件。旧研究适配器继续保留原有证据 pins 与门禁。

### 目录扫描范围与限制

目录知识库在各层排除 `.git` 和 `.outcomehub`，遵循所选内容目录内的 `.gitignore`，不读取机器全局忽略规则。大型附件通过 64 KiB 缓冲区流式计算 SHA-256，参与版本记录；按需返回文本时仍限制为 1 MiB。每次操作合计最多扫描 65,536 个目录条目、读取 8 GiB 内容、递归 32 层、执行 45 秒，重复扫描也计入总预算。忽略文件最多 4096 行，每行最多 4096 字节，并保留 1 MiB 文件限制。开发构建也会优化哈希依赖，以满足大型目录的固定时限。

直接读取和发布路径执行同样的忽略规则；符号链接、特殊文件、越界路径及扫描期间的内容变化会明确失败。目录版本以 `directory-v2:` 标识新的内容和忽略策略；旧版本前置条件需重新预览，历史回执不重写。错误由稳定代码和路径、大小、限制等参数组成，界面负责本地化展示。
