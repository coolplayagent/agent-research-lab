# 05 研究证据与版本谱系

[文档首页](../00-index.md) · [本目录](00-index.md) · [English](../../en/design/05-evidence.md)

## 主题、研究对象与版本

主题引用既有协作群。研究对象可为仓库、Agent、工具、模型、工作流、数据集、提示词或其他类型；主题和对象更新使用乐观 revision，保持归属稳定。知识内容仍在 SuperPOD，本地只保存协调元数据。

版本节点只追加，含版本引用、最多四个已存在父节点、可选源码/提示词/策略/SuperPOD 提交和关联群目标。边仅在同一对象内，父节点先存在保证无环。多个子节点表示分支，多父节点表示重组；相同请求幂等，替换既有节点拒绝。

评估状态从目标执行与主持人验收派生。worker 成功提交仍待验收，无关联目标的节点未评估。引用与声明的提交只是来源元数据，不构成独立晋级证据。研究回执还需与冻结尝试和四项绑定完全匹配；旧回执/节点仍可读，缺少新证据则未评估；新研究在版本节点下追加不可变 assessment，规则见下文。

宿主 API 为 `GET /api/im/topics`、`GET /api/im/subjects`、`GET /api/im/evolution`、`POST /api/im/research`（intent `manage-research`）。列表用稳定 ID 游标，图用持久 sequence 游标；存储服务的增量 SQLite schema v5 管理主题、对象、节点与父边。图支持过滤、分页、缩放、键盘选点和证据查看。

## 可重算谱系

`evolution lineage REQUEST.json --output STATE/evolution/lineage.json` 基于既有 `PromptRegistry` 生成可重算回执。请求包含 `registry_file` 和 `study`；后者带有 `task_kind`、固定的 `policy_version` / `superpod_commit`、宿主冻结的 `expected` 快照绑定、开发观测 `observations`、待评估/扩展项及评估预算。研究观察应用的**系统设置 → 群体演化**投影已校验回执，不暴露提示词正文或试验输入；AI-IM 右侧版本演化展示当前群关联主题的版本与评估状态。

报告区分策略自身表现和后代汇总表现，对重组谱系共享后代去重，未完成工作也计入预算。验证/保留集观测、变化绑定和重复试验会被拒绝。这是受 HGM 启发的谱系诊断，不是 HGM Thompson sampling 调度器复现。候选激活继续受评估、保留集隔离、晋级、发布和安装门禁约束；策略分支不会创建新数字人身份或共享可变实验记忆。

## 独立评估与晋级

注册不激活提示词。晋级要求至少三任务族和重复团队配对实验；新能力还需保留集迁移和消融。每类任务保留一个稳定、两个专门、两个探索策略；探索从 25% 起步，完整十次实验后调整，限制在 10–50%。正式规则提案保持隔离。

冻结的宿主预期上下文必须与实测匹配；未知字段、过期绑定、缺失测量及严重回归使门禁失败。合成示例不能替代实测。保留集、门禁输入和回执在宿主私有区域，不能被候选写挂载访问；仅分目录不是操作系统隔离。

公开研究输入仍是 [research/insights.md](../../../research/insights.md)，新任务冻结远程默认分支提交与内容摘要；完整知识及来源归档归属 SuperPOD。操作见[实验指南](../guide/05-experiments.md)与[交付指南](../guide/06-delivery.md)。

## 场景无关的迭代协调

平台分离协作、迭代协调和场景执行。协作核心拥有身份、群组、消息和目标；通用迭代引擎拥有冻结输入、轮次、候选版本、独立评估、主持人验收、可选激活及反馈；场景适配器拥有领域执行与证据要求。引擎不假定 CLI、仓库、MR、厂商或四人团队，无研究配置也能启动。

通用协作接受外部 worker。内置 `design-review` 让绑定 Agent 提出和独立评审结构化方案，无需 Git/MR/构建；真实提交由宿主记录证据并显式验收。可选 `research` 保持只读调查，`software-evolution` 增加仓库实现与交付策略。四 Agent CLI 研究只是一种部署配置；研究本平台另用独立运行与对象。

`GET /api/im/iterations` 支持 `group_id`、`scenario_id`、`after`、`active`，返回完整运行记录。`POST /api/im/iterations` 需 `manage-crystal` intent，封套含 `request_id`、`run_id`、`revision`、以 `operation` 标记的 `action`；创建时冻结带目标标准、场景参数、对象、基线、分工与预算的 `input`。暂停、继续、停止使用相同 revision 绑定的幂等封套。暂停阻止新领取/新轮次，已领取工作仍有界；停止取消当前轮。已领取切换阶段的激活须先经宿主核对结算，期间暂停与停止受隔离约束。

候选、评估、验收、激活、轮次完成分别记录，并核对当前目标和尝试。迭代内目标不能通过普通目标 API 验收、取消或重试，须用迭代控制保持证据与生命周期一致。

同一源码提交的重复研究在同版本节点下追加独立不可变 assessment，各自绑定目标、分工尝试及逐任务的源码、提示词、策略和 SuperPOD。可选 CLI 核对器经存储客户端分页读取目标，在私有状态恢复游标；只创建冻结 Job 或匹配工作证据支持的引用，不完整/不一致历史保持未评估。不推断父边、虚构晋级或复制 SuperPOD 知识，保留宿主编辑的主题和对象。

群状态事件刷新迭代及可见 assessment，即使群目录未变。重连重新拉取，请求代次隔离切群，较低 revision 不能覆盖新视图；版本详情链接最近评估、目标与证据。
